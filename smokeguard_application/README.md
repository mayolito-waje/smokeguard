# SmokeGuard Application

The SmokeGuard dashboard and backend: Wi-Fi CSI + air-quality smoking-activity
detection, live charts, detection history, and monthly PDF reports. Everything runs
in Docker Compose.

For the ESP32 hardware, firmware flashing, hotspot, and MQTT setup, see the
[repository README](../README.md).

## What runs

```
ESP32 Rx ──MQTT──> mosquitto ──> backend ──> influxdb
                                  │
                                  └──WebSocket/REST──> frontend (nginx) ──> browser
```

| Service | Purpose | Host port |
|---|---|---|
| `frontend` | React dashboard served by nginx; proxies `/api` and `/ws` | `APP_PORT` (8080) |
| `backend` | FastAPI, WebSocket stream, detection, PDF reports, SQLite stores | `BACKEND_PORT` (8000) |
| `influxdb` | Time-series storage for CSI and air-quality readings | `INFLUX_PORT` (8086) |
| `mosquitto` | MQTT broker the ESP32 devices connect to | `MQTT_PORT` (1883) |

## Prerequisites

- Docker Engine with Compose v2 (tested with Docker 29 / Compose 5).
- **x86_64 Linux**: TensorFlow 2.21 CPU wheels used by the backend are
  x86_64-only. ARM hosts (e.g. Apple Silicon) cannot build the backend image.
- About 5 GB of free disk and 2 GB of RAM for the images/runtime.
- Ports 8080, 8000, 8086, and 1883 free, unless overridden.

## Quick start

```bash
cd smokeguard_application
docker compose up --build -d
```

The first build downloads TensorFlow and can take several minutes. Then open:

**http://localhost:8080** — log in with **admin / admin** on a fresh install.

Useful commands:

```bash
docker compose ps                 # service health (mosquitto-init exits 0 by design)
docker compose logs -f backend    # backend/MQTT/detection logs
docker compose down               # stop, keep data
docker compose down -v            # stop and delete all data (destructive)
```

If you already run Mosquitto, uvicorn, or InfluxDB on the host, stop them first (or
change the port variables) — see [Troubleshooting](#troubleshooting).

## Configuration

No `.env` is required. Compose uses development defaults; a `.env` file in this
directory is read for `${...}` interpolation and overrides them. It is **not**
injected into the containers wholesale, and the internal addresses
(`MQTT_HOST=mosquitto`, `INFLUXDB_URL=http://influxdb:8086`) are fixed in
`docker-compose.yml`.

| Variable | Default | Purpose |
|---|---|---|
| `APP_PORT` | `8080` | Dashboard host port |
| `BACKEND_PORT` | `8000` | Backend API/WebSocket host port |
| `INFLUX_PORT` | `8086` | InfluxDB UI/API host port |
| `MQTT_PORT` | `1883` | Broker host port used by the ESP32 devices |
| `MQTT_USERNAME` / `MQTT_PASSWORD` | `esp32` / `mosquitto` | Broker + backend; firmware must match |
| `MQTT_TOPIC_DATA` | `home/csi/data` | CSI CSV stream |
| `MQTT_TOPIC_STATUS` | `home/csi/status` | Receiver status JSON |
| `MQTT_TOPIC_SMOKE` | `home/smoke_sensor/data` | Air-quality CSV stream |
| `NTP_SERVERS` | `pool.ntp.org,time.google.com,time.cloudflare.com` | Backend internet/NTP probe servers (comma-separated) |
| `NTP_TIMEOUT_S` | `1.0` | Per-server probe timeout |
| `NTP_RECHECK_INTERVAL_S` | `300` | Probe refresh interval; `0` = startup + manual refresh only |
| `TIMESTAMP_MAX_SKEW_S` | `300` | Live timestamp validity window; implausible values are host-corrected |
| `INFLUXDB_ADMIN_USER` / `INFLUXDB_ADMIN_PASSWORD` | `admin` / `smokeguard-admin` | InfluxDB UI login |
| `INFLUXDB_TOKEN` | `dev-influx-token-change-me` | Shared by InfluxDB init and the backend |
| `INFLUXDB_ORG` / `INFLUXDB_BUCKET` | `smokeguard` / `csi_data` | InfluxDB organization/bucket |
| `JWT_SECRET` / `PASSWORD_RESET_SECRET` | development values | Login token signing / password reset |
| `TZ` | `Asia/Manila` | Local display, month grouping, and PDF timestamps (record times stay UTC epoch) |
| `VITE_GITHUB_REPO` | `https://github.com/mayolito-waje/smokeguard` | Repository linked from Model Info source rows (build-time; rebuild the frontend after changing) |

Notes:

- An existing development `.env` is reused automatically (its `JWT_SECRET`,
  `MQTT_USERNAME`, `INFLUXDB_TOKEN`, etc. override the defaults). Do not copy
  `.env.example` blindly: its `<generated by ...>` placeholders are not real
  secrets. Either omit `.env` or set real values.
- Changing `MQTT_USERNAME`/`MQTT_PASSWORD` requires recreating the broker init:
  `docker compose up -d --force-recreate mosquitto-init mosquitto`.
- Changing `INFLUXDB_TOKEN`, org, or bucket after InfluxDB initialized requires
  deleting the InfluxDB volume (see below).
- Host port overrides are for debugging only. Devices must use the published
  `MQTT_PORT`.
- The backend's internet/NTP probe uses outbound **UDP 123** from the container.
  Docker bridge NAT normally permits it. If UDP 123 is blocked, the dashboard
  badge reports a connection error, but MQTT ingestion and host-clock timestamp
  correction keep working — the probe is advisory.
- The **Model Info** tab is built from the static
  `frontend/src/data/modelInfo.ts` snapshot, so it needs no **runtime**
  variables; update that module after retraining. Its provenance links use
  the build-time `VITE_GITHUB_REPO` (defaults to this repository) — after
  changing it, rebuild the frontend:
  `docker compose up --build -d frontend`.
- When running `scripts/mockup_detection_event.py` against the Compose stack,
  set `TIMESTAMP_MAX_SKEW_S=3600` in `.env` and recreate the backend: the
  mockup's clean-air baseline is intentionally backdated 600 s, while the
  default ±300 s window would correct it to receive time.

## Data and persistence

| Volume | Contents |
|---|---|
| `backend-data` | `/data/detection.db` (detection events, settings/static background) and `/data/auth.db` (admin user) |
| `influxdb-data` | CSI and smoke time-series |
| `mosquitto-auth` | Generated Mosquitto password file |

`docker compose down -v` deletes all three and resets the admin account to
`admin/admin`. Use `docker compose down` to keep the data.

The local `detection.db`, `auth.db`, `influxdb_data/`, and `sample_csv_output/` in
this checkout are **not** used by Docker.

### Migrating an existing local detection history

If you want the detection history/admin account from a local run inside Docker,
copy the SQLite files into the volume once (stop the local backend first so WAL is
checkpointed):

```bash
docker compose up -d backend
docker compose cp ./detection.db backend:/data/detection.db
docker compose cp ./auth.db backend:/data/auth.db
docker compose exec -u 0 backend chown 10001:10001 /data/detection.db /data/auth.db
docker compose restart backend
```

Export InfluxDB data separately if you need the old CSI/smoke readings.

## Using the dashboard

- **Live**: CSI strip chart, VOC and air-quality panels, receiver/MQTT status.
- **Detection**: enable it in the sidebar. Models load in the background at
  startup. Click **Capture static background** while the room is quiet (the CSI
  path needs it; at least 300 buffered CSI packets).
- **History**: pick a month, filter by detection class, open an event, or download
  the monthly **PDF report** (all classes).
- **Model Info**: a read-only metrics reference — CSI 7-class and binary
  results, the sensor SVM holdout, simulated late-fusion results, confusion
  matrices, per-class tables, and plain-language metric definitions. The values
  are a static snapshot from the training notebooks and model sidecars
  (`frontend/src/data/modelInfo.ts`); fusion is explicitly labelled simulated.
- Detection and both scores need a stream of air-quality samples on
  `home/smoke_sensor/data` — see the [hardware README](../README.md#smoke-sensor-data).
  Without that stream the dashboard still shows CSI, but the detection pipeline
  does not evaluate.

## Testing data without hardware

With `mosquitto-clients` on the host (adjust credentials/port if overridden):

```bash
# Replay a few recorded CSI lines (if sample_csv_output/csi_data.csv exists)
tail -n +2 sample_csv_output/csi_data.csv | head -5 | \
  mosquitto_pub -h localhost -p 1883 -u esp32 -P mosquitto -t home/csi/data -l

# One air-quality sample (16-field format)
mosquitto_pub -h localhost -p 1883 -u esp32 -P mosquitto \
  -t home/smoke_sensor/data \
  -m "$(date +%s).000000,10,12,14,16,18,20,22,24,26,29.88,999.88,51.17,331.28,112.08,-42"
```

`GET /api/health` and `/api/status` show packet counts and MQTT state.
`scripts/mockup_detection_event.py` can publish complete mock detection events over
MQTT for UI testing.

## Troubleshooting

**Port already in use** — stop the conflicting host service
(`sudo systemctl stop mosquitto`, local uvicorn, local InfluxDB) or start with
overrides, e.g.
`APP_PORT=8081 BACKEND_PORT=8001 INFLUX_PORT=8087 MQTT_PORT=1884 docker compose up --build -d`.
Remember to point the firmware at the overridden MQTT port.

**Backend logs "InfluxDB not reachable"** — the backend connects to InfluxDB only at
startup and does not reconnect. Check `docker compose logs influxdb`; after fixing
InfluxDB, `docker compose restart backend`. A token/org/bucket mismatch after the
volume was initialized requires `docker compose down -v` (deletes history).

**Login fails** — `admin/admin` is bootstrapped only when the auth volume is new or
empty. After a password change, use the API reset flow documented in
[CLAUDE.md](CLAUDE.md). A password reset never happens automatically.

**MQTT badge is disconnected / no data** — verify the broker credentials and
topics match the firmware, the devices can reach this machine on the published
`MQTT_PORT`, and the firewall allows it. The receiver status topic is retained, so
`mosquitto_sub ... -t 'home/csi/status' -v` should show JSON even between packets.

**No smoke detections** — detection needs air-quality samples (and a 600 s baseline)
plus a captured static background. See the
[hardware README](../README.md#smoke-sensor-data).

**PDF report button says it failed** — restart the backend after code changes
(uvicorn is not running with `--reload` inside the container). Empty months still
produce a valid zero-detection PDF; a missing logo only drops the logo.

**Mosquitto credential changes not applied** —
`docker compose up -d --force-recreate mosquitto-init mosquitto`.

**Build fails with a Docker Hub connection reset** — BuildKit still needs to pull the
base images (`python`, `node`, `nginx`, `influxdb`, `mosquitto`). Retry the build or
configure a registry mirror. The Dockerfiles intentionally use Docker's built-in
frontend and do not pull a separate `docker/dockerfile` syntax image.

**ARM host** — the backend image cannot build because TensorFlow 2.21 has no
aarch64 wheel; use an x86_64 host.

## Security

The Compose defaults are development values. Before exposing this beyond a trusted
LAN, change `JWT_SECRET`, `PASSWORD_RESET_SECRET`, `INFLUXDB_TOKEN`,
`INFLUXDB_ADMIN_PASSWORD`, and `MQTT_USERNAME`/`MQTT_PASSWORD`. MQTT is plaintext
(no TLS). The admin auth is a proof of concept; JWTs are stateless and are not
revoked on logout.
